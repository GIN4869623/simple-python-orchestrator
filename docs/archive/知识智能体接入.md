# 知识智能体接入

- 接口地址：`http://192.168.1.103:18001/api/knowledge/answer`。
- 调用方式：HTTP POST，`Content-Type: application/json`，不使用 JSON-RPC 包装。
- 实现：`src/simple_orchestrator/knowledge_http.py` 中的 `KnowledgeHttpAdapter`。

## 启用

只启用真实知识接口，其他智能体继续使用 Fake：

```bash
./run "请解释：认知选频技能在发送前需要做什么？请用两句话回答。" --planner fixed --knowledge-api-url --fake-outcome succeeded
```

`--knowledge-api-url` 不带值时使用上述地址，也可显式传入其他 HTTP(S) 地址。
或者在 `.env` 设置 `KNOWLEDGE_API_URL=http://192.168.1.103:18001/api/knowledge/answer`。
本地 `.env` 已设置该地址，当前可直接运行：

```bash
./run "解释 QPSK 原理"
```

未配置此变量且未传该选项时，保留原有 Fake 行为。
启用真实知识接口后不再显示 Fake 回复选择菜单，其他 Fake 默认使用成功方案。
`--fake-outcome` 可显式调整其他 Fake 的结果，不影响真实知识接口。
示例增加“请解释”以便 FixedPlanner 将包含“发送”的问题识别为知识问答。

也可与 `--remote-agents` 一起使用，此时仍须配置 DeviceManager 和 USRP 地址，
并使用 `--parameter-policy strict`。配置了此 HTTP 接口时优先于 `KNOWLEDGE_RPC_URL`。
超时沿用 `--rpc-timeout` / `ORCHESTRATOR_RPC_TIMEOUT`，默认 30 秒。
鉴权使用 `X-Knowledge-API-Key` 请求头，密钥通过 `.env` 中的 `KNOWLEDGE_API_KEY` 配置，
不复用其他智能体的 `ORCHESTRATOR_RPC_TOKEN`；认证头不写入日志。

## 请求

编排器内部传入 `{"message": "问题"}`，适配器转换为：

```json
{
  "request_id": "每次调用生成新的 UUID",
  "sender": "编排智能体",
  "question": "解释 QPSK 原理",
  "knowledge_domain_ids": [],
  "top_k": 3,
  "model_profile": "local"
}
```

`question` 去除首尾空白后必须为 1～2000 字符；超出长度时直接报错，不截断问题。
只有一个知识问答任务时，直接发送用户原问题，保留用户指定的回答长度、格式和换行。
拆分出的知识子任务优先使用 `inputs.question`（或 `inputs.query`），未提供时使用子任务描述。
仅在需要时附加具体输入条件、依赖结果、操作指导引用和设备信息，不重复用户原话。
规划器生成的 `expected_output`、`completion_criteria` 保留在编排器内部，不拼入知识问题。
`knowledge_domain_ids` 固定为空数组，表示不限领域。
`top_k` 按本次示例默认使用整数 `3`；`model_profile` 默认使用 `local`。
Python 构造适配器时可指定 `top_k`（整数 1～20）、`model_profile`（`local` / `cloud`）和 `sender`。

请求追踪编号每次调用独立生成，包括重试。原编排请求、任务、尝试编号保留在日志元数据中，
并通过 `knowledge_request_id` 与知识接口报文关联。

## 响应

```json
{
  "request_id": "kb-answer-001",
  "sender": "知识库",
  "status": "success",
  "summary": "发送前需要先扫描频段，再选择合适的频点。",
  "data": {
    "knowledge": "这里是知识库返回的完整回答，保留全部内容和换行。"
  },
  "error": null
}
```

只消费 `status`、`summary`、`data`、`error`；忽略其他顶层字段。
接口成功状态固定为 `success`，映射为编排器内部的 `succeeded`。
失败状态沿用 `failed`、`rejected`、`unknown`；未定义的状态按响应异常处理。
`data` 原样保留，成功响应必须包含字符串 `data.knowledge`，不删减内容、不折叠换行。
`summary` 必须是字符串，`error` 为字符串或 null。
HTTP 错误、连接失败、超时和格式异常会转为任务调用异常，并记录到现有智能体日志。

此接口只提供知识回答；没有实现可信 Skill 索引和读取接口，不能代替 USRP 物理任务的 Skill 前置校验。
