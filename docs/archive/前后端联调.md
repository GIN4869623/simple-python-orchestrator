## 启动

在 Python 项目的 `.env` 中配置独立的接口密钥，供 Next.js 服务端使用：

```dotenv
ORCHESTRATOR_API_HOST=192.168.1.106
ORCHESTRATOR_API_PORT=18002
ORCHESTRATOR_API_TOKEN=<随机密钥>
```

在 Python 项目目录运行：

```bash
./serve
```

它复用 `.env` 中的 Ollama、知识服务及智能体配置，也支持原有 `--planner`、
`--remote-agents` 等参数。HTTP 模式没有终端输入菜单，Fake 默认成功。
`./serve --planner fixed` 可在无需 LLM 的情况下联调接口。每个请求单独创建编排器，
服务同一时间只执行一个任务，其他提交返回 HTTP 429，不自动重试。

前端项目的 `.env.local` 配置：

```dotenv
ORCHESTRATOR_API_URL=http://192.168.1.106:18002
ORCHESTRATOR_API_TOKEN=<同一随机密钥>
ORCHESTRATOR_API_TIMEOUT_MS=600000
```

这些变量只用于服务端，不能加 `NEXT_PUBLIC_` 前缀。开发服务器通常会自动加载环境文件改动；
如果没有加载则重启前端进程。两个 `.env` 文件均不应提交到版本库。
本机 IP 变化后，需要同步修改后端监听地址与前端的 `ORCHESTRATOR_API_URL`。

下面按新电脑也是 Linux、前端继续留在 `192.168.1.103` 说明。通常只需改环境和配置，

   `src/simple_orchestrator/api.py`、`agents/` 和 `pyproject.toml`。

   `0.0.0.0` 用于服务监听；前端连接时填写新电脑实际 IP。
   当前其他服务地址如下。如果它们仍在原设备上，且新电脑可以访问这些地址，就保留：


   如果模型或知识服务也迁移，更新对应地址及必要的模型名和密钥。
   后端继续调用原有 Ollama 服务时，新电脑不需要再次安装和下载该模型。

4. 在前端设备的 `/home/njupt/Desktop/Muti-Agent-main/.env.local` 修改：

   ```dotenv
   ORCHESTRATOR_API_URL=http://<新电脑IP>:18002
   ```

   修改后重启前端服务。若前后端以后放在同一台电脑，地址可使用

5. 在新电脑的项目目录运行 `bash ./serve`，确保前端设备能访问新电脑的 TCP 18002 端口。
   刷新网页，确认“协同编排智能体”标题旁连接灯变绿，然后提交任务验证。

## 接口与页面行为

- Python `GET /health`：返回服务状态、忙碌状态与运行配置。
- Python `POST /api/orchestrator/runs`：接收 `{"request": "任务文本"}`，文本为 1～2000 字符，
  立即返回 HTTP 202 及 `request_id`。
- Python `GET /api/orchestrator/runs/<request_id>`：查询执行状态，运行时返回 `running`，
  完成后返回完整结果。最近 20 个任务保存在服务内存中，重启后需要检查日志确认先前执行状态。
- Python `POST /api/orchestrator/run`：仍提供同步调用，供简单脚本使用。
- 所有接口都要求 `Authorization: Bearer <ORCHESTRATOR_API_TOKEN>`。
- 返回 JSON 包含 `request_id`、`status`、`final_answer`、`intent`、`plan_history`、
  `task_statuses`、`results`、`reviews`、`handling_mode` 和 `runtime`。
  `handling_mode` 表示实际路径：`direct`、`fixed_workflow` 或 `orchestrated`；
  需要补充信息时还返回 `clarification_questions`。完整知识回答保留在任务结果的
  `data.knowledge`；历史计划和全部尝试也保留。
- 网页的“协同编排智能体”区域提供任务输入、执行中提示、最终状态、任务结果和执行复盘。
  页面只显示连接和执行情况，不标记 HTTP/Fake 等实现方式。
- 参数不全时返回 `needs_clarification`，网页显示补充要求；用户在原任务中补充并重新提交。
  这是一次新运行，不是恢复 checkpoint。
- 网页提交后台任务后每 1.5 秒查询一次结果，避免大模型长时间推理占用单个 HTTP 连接。
  尚未提供逐节点实时推送；现有其他智能体的 SSE 事件流继续独立运行。
- 如果请求超时，前端不会自动重试，需先检查后端是否已完成。

原有物理操作的限制仍由主图执行；增加网页入口不会放开远程 USRP 执行。
Python HTTP 入口用于当前可信局域网的开发联调，采用标准库实现，不增加依赖。
